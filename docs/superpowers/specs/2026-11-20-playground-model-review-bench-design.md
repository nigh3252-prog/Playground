# Playground Model Review Bench

## Goal
One Playground page for inspecting and polishing the model collection, and one catalog other assistants can use to find actual game assets. Ryan can talk through models using his existing recorder and refer to exactly one asset/version in the transcript. Original standalone viewers are preserved for archival and specialized controls, not embedded in the bench.

## Approaches
- A directory launching the old viewers is fast but fails the shared review flow and does not expose individual source files.
- Preloading every mesh and texture in one scene makes large packs painful on a phone and cannot scale as batches are added.
- Selected: one native WebGL scene and catalog. Every imported model/version is in the same browseable collection, with identical controls. Choose a card to inspect its own geometry directly, on demand; no iframe, tab change, or separate viewer startup, and no need to download the whole archive. Preserve an explicit public original link only where cleared/appropriate.

## First slice
- Playground route `/models/`, reachable from the existing homepage. Reuse the repository's existing static/web runtime and local Three.js modules where compatible. Responsive and keyboard accessible; support quick previous/next without losing track of exact revision. Distinct selectable entries for deliberate variants; only collapse byte-identical duplicate uploads after checking.
- First batch: Dot (original small workshop robot with one bright eye and an authored idle), Crocodilian (verified static articulated mesh), and White Mech (four verified embedded animations, including Walk_Preview) subject to provenance checks. If White Mech rights are unclear, ship only cleared alternatives. Grow the catalog in later small audited batches, then add other genuinely reusable assets from the existing Armory without duplicating bytes. No fictional substitute if actual source cannot be recovered.
- Shared orbit, zoom and fit; animation picker for exactly the embedded clips, play/pause, scrub and loop, and explicit static/unrigged state when no clips. Do not invent a walk for a static model. A model can be viewable without being rigged, and rigged without supplying walk clips.
- Keep the viewport and a short, readable name/version prominent, with previous/next and a copy-link action (the copied link includes stable model ID and version). Hide detail until requested. Ryan will use his own voice recorder; no feedback widgets, ratings, notes, recordings, microphone permissions or transcription.
- Keep measured triangles, mesh/texture counts, file size, clip count, known rig status and credits in the machine-readable catalog and optional Details view only. Clearly distinguish original scale from normalized inspection scale and an unknown trait from zero. Never infer phone performance from file size alone. The catalog links each approved direct GLB and records credits, alias, source version and verified license/status. No public Drive IDs, tokenized links or private reference art; ambiguous rights stay out of public batches. Do not redistribute source-hosted NoAI assets or label unclear licenses reusable.

## Future seams, not v1 promises
Use stable asset IDs/version hashes, original units/up-axis where known, and optional rig profile, clip kind/source, attachment slot/transform and compatibility identifiers. Later inventory actual humanoid joints/rest poses, map one existing walk onto one compatible rig, validate foot contact/root motion, then grow deliberately to other rigs. For modular mechs, preserve separate authored bodies/arms/legs and gear where they exist, standardize shoulder/hip/gear sockets with orientation and units, and prove one compatible swap pair before adding a mixer. Never promise arbitrary meshes will bolt together or procedural retargeting without a skeleton. Do not rip or create derivative source assets without clearance.

## Acceptance
First-batch actual assets parse/verify, same scene supports each model, one real clip plays/scrubs, static model says so, previous/next and exact deep link work including browser navigation on phone and desktop, asset/model identity survives deep link and reload, visible chrome stays minimal with details closed, and all source credits are documented. Initial load must not fetch every asset binary; repeated switches must not keep growing object/texture counts or leave old models on stage. No changes to other Playground games or deployment visibility. New bench changes start in a draft PR scoped separately from #22.
